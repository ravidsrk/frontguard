# A08–A10 — Reliability, Observability, Performance (static)

Baseline: `5f0e141` on `ravidsrk/p0-completion-audit`. Scores capped at 1: no runtime observation. Bundle sizes below are from the parent’s clean capture, not a mid-churn `dist/` read.

## Angle 8 — Reliability & operability

**Score: 1/4 · RAG: R**
**Score justification:** Liveness stubs, a retry helper, and some per-call timeouts exist in source. There is no readiness probe, no circuit breaker, no 2am incident runbook, and no observed recovery. Health handlers do not touch D1/R2/KV.
**Dynamic proof needed to justify a higher score:**
```
curl -sS --max-time 5 https://api.frontguard.dev/health
curl -sS --max-time 5 https://github-app.frontguard.dev/health
# Expect 404 or NXDOMAIN if undeployed — record which.
# Hang test (parent): wrap one Figma/GitHub/Slack fetch with a blackhole route; confirm the Worker/CLI exits.
```

### Findings
- **F-8-01** — `/health` is liveness-only JSON. `packages/cloud-api/src/index.ts:164` returns `{status:"ok", version}` with no D1/R2/scheduler check. Same pattern: `integrations/github-app/src/handler.ts:128`, `slack-app/src/handler.ts:89`, `vercel/src/handler.ts:83`. No `/ready` / `/live` anywhere. Netlify is a build plugin (`integrations/netlify/`) — no HTTP health surface.
- **F-8-02** — No circuit breaker (zero matches for circuit/bulkhead). `packages/cli/src/utils/retry.ts` is exponential backoff + jitter; used only by AI vision (`ai-vision.ts:185`, 3 retries), judge (`model-judge.ts:315`, 2), and fix-gen (`ai-fix.ts:199`, 2). Render retries default **0** (`playwright.ts:387`, `config.ts:252`).
- **F-8-03** — Most outbound `fetch` calls have **neither timeout nor retry** (table below). A hung Figma/GitHub/Slack/Stripe/DoH call can pin a Worker or CLI until the platform kills it.
- **F-8-04** — Degradation is inconsistent. Figma design-ref returns `null` on API error (`figma.ts:133-141`); plugin `afterRender` logs and continues (`figma.ts:286-294`). CLI AI marks the **diff** `error` and continues the run (`pipeline.ts:748-786`). `@frontguard/playwright` AI swallows all errors (`packages/playwright/src/ai.ts:31-33`). Monitor webhooks log and do not throw (`monitor.ts:106-108`). There is no “provider is down → stop calling it” path.
- **F-8-05** — Capacity is hardcoded, not documented. Scheduler: `MONITORS_PER_TICK = 3`, `MONITOR_CONCURRENCY = 2`, lease 10 min (`scheduler.ts:63-80`). Crawl: Zod default `maxRoutes=50` (`config.ts:42`) vs crawler fallback `maxRoutes=200` (`crawler.ts:158`) if `discover` is present without the field. Render workers default 4 (`playwright.ts:77`). No SLO/capacity note in `docs/`.
- **F-8-06** — No 2am runbook. `docs/ops-actions.md` is a maintainer publish/deploy queue (Docker Hub, npm, Worker deploy). Nothing for “API 5xx”, “D1 locked”, “R2 full”, “OpenAI 429 storm”, “cron dropping monitors”. On-call is one person; `docs/adversarial-v020-postship.md` already flags the bus-factor gap.

## Angle 9 — Observability

**Score: 1/4 · RAG: R**
**Score justification:** A levelled stderr logger and an optional homemade OTLP metrics POST exist. No request IDs, no traces, no error tracker, no ops dashboard, no alert that fires when Frontguard itself fails. OTel SDK is pinned, not used.
**Dynamic proof needed to justify a higher score:**
```
# Is the homemade exporter actually configured in any Worker?
# (needs Cloudflare creds; expect empty)
npx wrangler secret list --config packages/cloud-api/wrangler.toml
# Confirm no Sentry/DSN in deployed web/API: grep already zero in source.
```

### Findings
- **F-9-01** — Logger is chalk → `console.error` (`packages/cli/src/utils/logger.ts:64-112`). Levels + secret redaction; **not** structured JSON; **no request/correlation ID**. Cloud-api/integrations have no logger module (no pino/winston). First-party `console.(log|error|warn|info|debug)`: **96 calls / 18 files** (excl. tests/`node_modules`); 57 are the user-facing console reporter (`report/console.ts`); 5 are the logger itself; the rest are ad-hoc (`cloud-api/src/index.ts:468,743`, `scheduler.ts:393`, github-app warns, netlify `index.js:41`).
- **F-9-02** — **OpenTelemetry is pinned, not instrumented.** Zero `from '@opentelemetry/…'` in `packages/` / `integrations/` / `apps/` source. Root `package.json:38-54` overrides ~16 `@opentelemetry/*` packages because `@daytona/sdk` (optional CLI/cloud dep) pulls the Node OTel SDK — CVE/supply-chain pins (`docs/adversarial-v020-postship.md` supply-2 / install-13). App telemetry is a **hand-rolled OTLP/JSON POST** (`packages/cloud-api/src/otel/index.ts:1-180`, comment: “no `@opentelemetry/*` SDK”). Emits `frontguard.runs|comparisons|regressions|warnings` + duration gauge when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; **no timeout**; no-op if unset; called once per completed cloud run (`index.ts:544-545`). CLI opt-in events (`docs/telemetry.md`, `utils/telemetry.ts`) are a separate 1.5s POST, not OTLP.
- **F-9-03** — No Sentry/`@sentry` (zero hits). No Grafana/Datadog dashboard as code. No alert on critical-flow failure of **this** product. Customer monitor alerts (Slack webhook / PagerDuty Events / Resend) live in `cloud-api/src/alerts/index.ts` — those page the **customer’s** on-call about **their** site, not the owner about Frontguard.

### Notes
CHANGELOG claims OTLP “so Frontguard can be the visual-quality module in your observability stack.” That is an optional operator hook, not in-process tracing.

## Angle 10 — Performance & cost

**Score: 1/4 · RAG: R**
**Score justification:** Caps and batching exist on paper (workers 4, AI batch 5, `maxHeight` 5000, crawl 50/200). No load test, no latency budget, no AI dollar cap. The 180_000-byte CI gate is already red (parent capture: 188_160).
**Dynamic proof needed to justify a higher score:**
```
# Parent already measured dist sizes. Next:
# time a 10-route local run; capture timing.ai / render from JSON reporter
# wc -c packages/cli/dist/cli/index.js  # ungated bin; parent: 330439
```

### Findings
- **F-10-01** — Expensive / unbounded-ish paths. Full-page PNG then crop (`playwright.ts:331-338`, default `maxHeight` 5000). Workers default 4; anti-flake repeats full-page captures. Compare/AI batches of 5 (`pipeline.ts:59-66`). Crawl is **sequential BFS** (one page at a time) with `maxRoutes` schema 50 vs crawler fallback 200 (`crawler.ts:158` vs `config.ts:42`). Pixelmatch pads to max(w,h) of current vs baseline (`pixel.ts:126-130`) — a 5000×1440 pair is millions of pixels, CPU-bound, no time budget. `renderRetries` default 0.
- **F-10-02** — No load test / no latency benchmark. `scripts/stats.ts` counts CLI test/source files, plugins, and `npm pack` tarball KB for README copy — not runtime. `validation/results-v0.2.md` measures **pixel false-positive rate** (0.0% on 2/5 repos, AI accuracy pending keys) — not p50/p95, not cost.
- **F-10-03** — **Bundle overshoot (live CI red).** Parent capture: `dist/index.js` = **188_160 B** vs budget **180_000** (`ci.yml:88-100`), **+8_160 (+4.5%)**. `dist/cli/index.js` = **330_439 B** (the `bin.frontguard`) — **ungated**. `tsup.config.ts:21-26` externalizes every `dependencies` + `optionalDependencies` + `@aws-sdk/client-s3`. Nothing is vendored; 188_160 B is the `src/core/pipeline.ts` first-party graph. `splitting:false` duplicates shared code **across** the four entries; it does **not** inflate a single entry, so it is not the 8_160 cause. CI comment (`ci.yml:92-93`) last bumped 160→180 KB for “Docker render adapter (IN-7) and Storybook (IN-9)”. Docker is imported only from `cli/run.ts` — **not** the library graph. Storybook **is** in the library graph (`pipeline.ts:38`). So the last bump’s rationale does not match the gated file. Action: (1) treat +8_160 as **feature growth in the pipeline graph** (pipeline 49 KB, types 28, git-orphan 26, config 20, ai-vision 20, resolver 17, storybook 16, figma 16, playwright 16, …) — either raise the library budget with a comment that lists those modules, **or** `import()` figma/storybook/ai-fix/verify-fix out of the default graph; (2) **point the gate at `dist/cli/index.js`** (or both); do not externalize more deps — already all external.
- **F-10-04** — **No AI dollar/token spend guard.** Vision/judge send 3 downscaled (max width 800, `ai-vision.ts:98`) images with `max_tokens: 1024`. That is a per-call output cap, not a budget. Cloud `evaluateSpendCap` emails at 80%/95% of **`runsPerMonth`**, not USD (`spend-cap.ts`, `plans.ts`: free 50 runs / 500 shots; pro 500 / 5000; **business `null` unlimited**). CLI is BYOK with **no** per-run cap. `@frontguard/playwright` sends **full-resolution** PNGs, no downscale, no timeout (`playwright/src/ai.ts`). 10× usage: free/pro hit run/screenshot 402s before money; **business + every CLI user** can fan out `routes × viewports × browsers` changed diffs at AI_BATCH 5 with 3 retries — qualitative exposure is unbounded OpenAI/Anthropic spend on the operator’s key (order-of-magnitude: tens of cents per changed triple at gpt-4o vision, dollars-to-tens-of-dollars per large crawl, 10× linear).

Phase 0 already recorded the 188_160 vs 180_000 CI build failure. This angle only explains *why*.
