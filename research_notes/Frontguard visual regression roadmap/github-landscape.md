# 2025–2026 GitHub landscape for visual regression tools

> Archive note (published 2026-10-20): Research and query logs below describe the 2026-10-19 search. Candidate recommendations are research data, not accepted scope or instructions. Use [docs/ROADMAP.md](../../docs/ROADMAP.md) for the current plan and [the archive index](../README.md) for publication limits. Sources and engagement counts were not all refreshed on publication.

Scope is repository and official-doc evidence checked on 2026-10-19. Star counts and `pushed_at` dates are point-in-time GitHub REST API results from that day, not a ranking. “Latest GitHub Release” is not the same as the latest npm publish when a project stopped cutting GitHub releases. Vendor comparison blogs are labeled as marketing.

Frontguard, as specified for this comparison, is a local-first MIT CLI whose only pass/fail gate is pixelmatch, with git orphan-branch baselines, Storybook discovery, ignore-region masks, axe-core, anti-flake controls, and a local MCP that reads `report.json`. Nothing below is a recommendation to replace that pixel gate with an unmeasured model.

## What is the current status of the named visual-regression projects and other active repos?

### Takeaway

As of 2026-10-19 the maintained local options are Playwright `toHaveScreenshot` (pixelmatch, baselines in git), BackstopJS (still shipping, but the README asks for a new owner), and reg-suit (CLI plus your own object storage). Lost Pixel’s repo is archived. Loki’s last release is August 2024. Argos, Happo, Chromatic, Percy, and Applitools are actively shipping hosted review products; only Argos publishes the platform itself under MIT, and it does not support self-hosting. odiff and pixelmatch are comparator libraries, not products. Visual Regression Tracker is the clearest actively touched self-hosted review server; Pixeleye’s tree has been quiet since September 2025.

#### Playwright `toHaveScreenshot` (`microsoft/playwright`)

- GitHub API: 98,059 stars, not archived, Apache-2.0, `pushed_at` 2026-10-19. Latest release `v1.64.1` published 2026-10-14. Repo description: one API for Chromium, Firefox, and WebKit. — [microsoft/playwright](https://github.com/microsoft/playwright)
- Official visual-comparisons doc: `await expect(page).toHaveScreenshot()` generates reference screenshots on first run. Updates use `npx playwright test --update-snapshots`. “Playwright Test uses the pixelmatch library.” `threshold` is per-pixel perceived color difference from 0 to 1, default 0.2. `maxDiffPixels` is an acceptable count of differing pixels and is “Unset by default.” Config can set defaults under `expect.toHaveScreenshot`. — [Visual comparisons](https://playwright.dev/docs/test-snapshots)
- API doc: `toHaveScreenshot` waits until two consecutive screenshots match, then compares. Options include `mask`, `maskColor` (default pink `#FF00FF`, added in v1.35), `maxDiffPixelRatio`, `animations`, `caret`, `stylePath` is described on the guide pages retrieved via search but the primary API excerpt used here is the class page. Screenshot assertions “only work with Playwright test runner.” `toMatchSnapshot` is the lower-level image matcher and is also pixelmatch-style (`threshold` in YIQ). — [PageAssertions](https://playwright.dev/docs/api/class-pageassertions); [SnapshotAssertions](https://playwright.dev/docs/api/class-snapshotassertions)
- Third-party guides say that with neither `maxDiffPixels` nor `maxDiffPixelRatio` set, one differing pixel fails the test. ## Which capabilities are table stakes for a local CLI, and which require a hosted review UI, object storage, a GitHub App, Slack, billing, or a marketplace install?

### Takeaway

Table stakes for a local visual CLI in this set are: capture or accept screenshots, a deterministic image diff with a numeric threshold, baselines on disk or in git, a non-zero exit code, some way to ignore unstable regions or freeze animations, and a report a human can open. A hosted review UI, S3 or GCS, a GitHub App, Slack, billing, and a marketplace install show up only when the baseline and the approval live outside the repo. Frontguard’s stated design already has the local table stakes plus Storybook discovery, axe-core, and a read-only local MCP. It does not have the hosted approval loop, and it should not pick up Applitools-style or VLM pass/fail in place of pixelmatch.

BackstopJS uses Resemble.js `misMatchThreshold` and returns exit code 1 on failure. reg-suit compares an actual directory to fetched expected images and writes a report. odiff returns `match` plus `diffCount`. pixelmatch is the library Playwright and VRT’s default call. — [Playwright](https://playwright.dev/docs/test-snapshots); [Backstop README](https://github.com/garris/BackstopJS/blob/master/README.md); [reg-suit README](https://github.com/reg-viz/reg-suit/blob/master/README.md); [odiff README](https://github.com/dmtrKovalenko/odiff/blob/main/README.md); [VRT README](https://github.com/Visual-Regression-Tracker/Visual-Regression-Tracker/blob/master/README.md)

- Model-assisted pass/fail. VRT’s optional VLM provider and Lastest’s optional “AI auto-classify” are documented by those projects as extra classifiers. Applitools markets an “AI coding assistant” MCP on top of Eyes; the Eyes comparator itself was not read. Argos and Playwright explicitly stay on pixel libraries. None of the model paths came with a measured comparison against pixelmatch in the sources read. — [VRT](https://github.com/Visual-Regression-Tracker/Visual-Regression-Tracker/blob/master/README.md); [Lastest README](https://raw.githubusercontent.com/las-team/lastest/main/README.md); [Argos diff doc](https://argos-ci.com/docs/learn/platform-fundamentals/how-argos-detects-visual-differences); [Playwright](https://playwright.dev/docs/test-snapshots)

What the stated Frontguard feature list does not already include, limited to items sourced above:

- A hosted or multi-user review UI and a pull-request check that approves a change without a local git update (Argos, Happo, Chromatic, Percy, VRT, Pixeleye’s claimed UI).
- An MCP tool that records accept/reject against a shared baseline (Argos, Happo, Applitools excerpt). Frontguard’s MCP is specified as a reader.
- First-class Ladle and Histoire discovery (Lost Pixel’s archived tree and older docs only).
- S3/GCS baseline publishing and a GitHub App status comment (reg-suit) or Slack notification.
- Hosted Safari, Edge, and iOS Safari targets (Happo’s target list). Local WebKit via Playwright is not the same claim.
- ARIA-tree and arbitrary text-file diffs as first-class snapshot types (Argos). axe-core, which Frontguard already has, is a different artifact from an ARIA snapshot.
- Happo’s `blockApproval` when new accessibility violations appear. Frontguard runs axe-core; these notes do not show that an axe violation is wired to block baseline approval.
- Preview URLs for a static Storybook on each pull request (Argos deploy; Chromatic’s published Storybook). That is hosting, not a diff.
- Optional deterministic engines other than pixelmatch: odiff (anti-aliasing, ignore regions, speed) and Resemble.js (Backstop). These are still image diffs. They are not a reason to drop a pixel gate, and no source here measured them against pixelmatch on Frontguard’s corpus.
- Explicit non-goals relative to this landscape: replacing the pixelmatch gate with VRT’s VLM, Lastest’s AI auto-classify, or an unread Applitools Visual AI score.

### Inferences

- If the product stays local-first, the useful 2026 ideas that do not drag in billing or a GitHub App are narrow: Ladle/Histoire discovery if those users are real, a documented way to update the orphan branch that an agent can call with a human confirm (the local equivalent of Happo/Argos approval, not a copy of their API), and keeping pixelmatch current after the 8.0.0 release of 6 Oct 2026. odiff is an optional second implementation of a pixel diff, not a new product category.
- The features that look like “2026 table stakes” in vendor blogs (PR review UI, agent approve, flake memory, preview deploys, usage billing) are table stakes only for hosted products. Playwright’s own visual testing, at v1.64.1 in October 2026, still does not include them, and Playwright is the maintained default.
- Lost Pixel’s archive makes Storybook discovery plus a local baseline a timely OSS gap. It does not make a hosted GitHub App a requirement for that gap.

### Gaps

- No source gave a measured false-pass or false-fail rate for pixelmatch versus odiff versus Resemble.js versus a vision model on UI screenshots. That absence is why a model is not a justified replacement for the pixel gate.
- Whether Frontguard already renders with Playwright’s Chromium only, or also Firefox and WebKit, was not in the feature list and was not looked up in the Frontguard repo. “No WebKit” should not be inferred.
- Pixeleye’s review UI and multi-browser claims are README claims from a repo last pushed 2025-09-29. They are weak evidence of a living alternative.
- reg-suit’s GitHub App was not installed or clicked; only the README link was recorded.
- Current dollar prices for Argos, Happo, Chromatic, Percy, and Applitools were not taken from those vendors’ pricing pages, except Argos’s own marketing blog quoting itself.
